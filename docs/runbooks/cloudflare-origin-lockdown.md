# Runbook: Cloudflare Origin Lockdown + CF-Connecting-IP Validation (P0-1)

> **This runbook's ufw / nginx apply is a manual, human-authorized production
> step.** Nothing here runs automatically from CI or from the code change that
> shipped `cloudflare-real-ip.conf`. A human must SSH to the droplet and run
> these commands with explicit authorization.

## Purpose

The origin API (`root@159.223.45.213`) serves plain `:80` and sits behind
Cloudflare. Two gaps make the SlowAPI auth rate limits bypassable (P0-1):

1. **Attacker-spoofed `CF-Connecting-IP`.** nginx used to copy the
   client-supplied `CF-Connecting-IP` header straight into `X-Real-IP` /
   `X-Forwarded-For`. SlowAPI keys auth limits on the resulting remote address,
   so an attacker who reaches the origin directly (or via any proxy) could
   rotate `CF-Connecting-IP` to get a fresh rate-limit bucket per request.
2. **Open origin ingress.** Because `:80`/`:443` accept connections from any
   source — not only Cloudflare — the header above is fully attacker-controlled.

Defense in depth closes both:

- **nginx `cloudflare-real-ip.conf`** (shipped in `api/nginx/`) runs the realip
  module: `CF-Connecting-IP` is trusted **only** when the connection originates
  from a published Cloudflare range (`set_real_ip_from`). `$remote_addr` is then
  rewritten to the validated visitor IP, and every location block forwards that
  validated `$remote_addr` (never the raw header).
- **ufw** restricts origin `:80`/`:443` ingress to Cloudflare ranges only, so
  no non-Cloudflare host can reach nginx to supply a header at all.
- **uvicorn** (`gunicorn.conf.py` → `forwarded_allow_ips=127.0.0.1`) trusts
  `X-Forwarded-*` only from nginx on loopback.

## 1. Lock origin ingress to Cloudflare (ufw)

Allow SSH first (or you will lock yourself out), then allow `:80`/`:443` from
Cloudflare's IPv4 and IPv6 ranges only. `ufw` denies everything else by default
(the default-deny fall-through), so no explicit "deny all" rule is needed.

```bash
# Keep SSH reachable — set BEFORE enabling ufw.
ufw allow 22/tcp

# Allow HTTP + HTTPS from Cloudflare IPv4 ranges only.
for ip in $(curl -s https://www.cloudflare.com/ips-v4); do
  ufw allow from "$ip" to any port 80  proto tcp
  ufw allow from "$ip" to any port 443 proto tcp
done

# Allow HTTP + HTTPS from Cloudflare IPv6 ranges only.
for ip in $(curl -s https://www.cloudflare.com/ips-v6); do
  ufw allow from "$ip" to any port 80  proto tcp
  ufw allow from "$ip" to any port 443 proto tcp
done

# Default-deny fall-through blocks all other origin ingress on 80/443.
ufw default deny incoming
ufw default allow outgoing
ufw enable
ufw status verbose
```

> Re-running the loops after a Cloudflare range change **adds** new allow rules
> but does not remove stale ones. When ranges shrink, prune obsolete rules with
> `ufw status numbered` + `ufw delete <n>`, or reset and re-apply:
> `ufw --force reset` then re-run the block above.

## 2. Weekly cron — refresh `cloudflare-real-ip.conf`

Cloudflare publishes its ranges at `https://www.cloudflare.com/ips-v4` and
`.../ips-v6`. Regenerate the `set_real_ip_from` lines weekly, validate, and
reload nginx. Save as `/usr/local/sbin/refresh-cf-real-ip.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

SNIPPET=/etc/nginx/snippets/cloudflare-real-ip.conf
TMP="$(mktemp)"

{
  echo "# Auto-generated by refresh-cf-real-ip.sh — do not edit by hand."
  echo "# Source: https://www.cloudflare.com/ips/  ($(date -u +%FT%TZ))"
  echo "# IPv4"
  for ip in $(curl -fsS https://www.cloudflare.com/ips-v4); do
    echo "set_real_ip_from ${ip};"
  done
  echo "# IPv6"
  for ip in $(curl -fsS https://www.cloudflare.com/ips-v6); do
    echo "set_real_ip_from ${ip};"
  done
  echo
  echo "real_ip_header CF-Connecting-IP;"
  echo "real_ip_recursive on;"
} > "$TMP"

install -m 0644 "$TMP" "$SNIPPET"
rm -f "$TMP"

nginx -t && systemctl reload nginx
```

Install and schedule (weekly, Sunday 03:15 UTC):

```bash
chmod +x /usr/local/sbin/refresh-cf-real-ip.sh
# /etc/cron.d/refresh-cf-real-ip
echo '15 3 * * 0 root /usr/local/sbin/refresh-cf-real-ip.sh >> /var/log/refresh-cf-real-ip.log 2>&1' \
  > /etc/cron.d/refresh-cf-real-ip
```

> The same schedule should also re-run the ufw loops in section 1 so origin
> ingress and the realip snippet stay in sync with Cloudflare's ranges.

## 3. Deploy the nginx snippets

Both snippets live in the repo under `api/nginx/`. Copy them to the server's
`snippets/` directory (referenced by `oyechats-api.conf` via
`include /etc/nginx/snippets/...`):

```bash
cp api/nginx/cloudflare-real-ip.conf   /etc/nginx/snippets/cloudflare-real-ip.conf
cp api/nginx/oyechats-locations.conf   /etc/nginx/snippets/oyechats-locations.conf
nginx -t
systemctl reload nginx
systemctl restart oyechats-api
```

`oyechats-api.conf` already includes `cloudflare-real-ip.conf` immediately
before `oyechats-locations.conf` in the `:80` server block (and in the
commented `:443` block, ready for when TLS is enabled).

## 4. Manual verification

1. **Origin ingress is closed to non-Cloudflare hosts.** From a host that is
   NOT a Cloudflare edge (e.g. your laptop, direct to the origin IP):

   ```bash
   curl -m 5 -H 'CF-Connecting-IP: 1.2.3.4' http://159.223.45.213/health
   ```

   The connection must be **refused / time out** — ufw blocks it before nginx
   ever sees the request. If you get an HTTP response, ufw is misconfigured.

2. **Via Cloudflare, the app logs the true visitor IP.** Hit the public
   hostname (through Cloudflare) and confirm gunicorn/nginx access logs record
   the real client IP as `$remote_addr` — not a Cloudflare datacenter IP.

3. **Rotating `CF-Connecting-IP` no longer mints fresh rate-limit buckets.**
   Send repeated auth requests through Cloudflare while varying a spoofed
   `CF-Connecting-IP`; SlowAPI must keep counting against the same
   Cloudflare-validated `$remote_addr`, so the limit still trips. A rotating
   header must NOT reset the counter.
